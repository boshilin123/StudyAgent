# 学习与复习接口

状态：P5 自适应选择与检索讲解已实现  
适用题型：单选题、填空题、判断题  
依赖：[接口总览](接口总览.md)

## 1. 实现边界

- 会话、作答记录、掌握度和复习任务以 PostgreSQL 为事实来源，服务重启后可恢复。
- `practice`、`diagnostic` 和 `review` 每次答题后动态选择下一题；`mock_exam` 在开局固定题集。
- 三类客观题均采用本地确定性判分，不调用 LLM，也不经过 Agent 回流。
- 作答记录、会话统计、掌握度和复习任务在同一事务中更新。
- `submission_id` 提供作答幂等；相同请求返回原结果，不同请求复用时返回 `409`。
- Redis 保存可从 PostgreSQL 重建的运行态 checkpoint，缓存丢失不影响学习事实。
- 答错时由 LangChain 根据题目绑定的真实原文生成讲解；模型失败自动退回题库解析。

## 2. 创建学习会话

`POST /api/study/sessions`

```json
{
  "knowledge_base_id": "d5737c62-e131-461b-9b9f-c602e59d6f0b",
  "mode": "practice",
  "question_count": 10,
  "question_types": ["single_choice", "fill_blank", "true_false"],
  "difficulty_min": 1,
  "difficulty_max": 5
}
```

`mode` 当前支持：

- `diagnostic`：提高知识点覆盖和新题优先级。
- `practice`：综合薄弱度、到期复习、历史题目、难度匹配和题型多样性动态选题。
- `review`：只选择已经到期且存在可用题目的知识点；无候选题返回 `409 NO_DUE_REVIEWS`。
- `mock_exam`：创建时固定题集和顺序，答题表现不会改变本轮题目。

响应 `201`：

```json
{
  "id": "50e031ba-6de0-4a15-89d7-250df0e5cc4c",
  "knowledge_base_id": "d5737c62-e131-461b-9b9f-c602e59d6f0b",
  "mode": "practice",
  "status": "active",
  "planned_question_count": 1,
  "answered_question_count": 0,
  "correct_count": 0,
  "incorrect_count": 0,
  "total_score": 0,
  "max_total_score": 0,
  "started_at": "2026-09-28T01:16:31Z",
  "finished_at": null,
  "current_question": {
    "id": "faadcf55-63af-4430-9326-60be2b8806a6",
    "sequence": 1,
    "question_type": "single_choice",
    "stem": "……",
    "options": [{"key": "A", "text": "……"}],
    "difficulty": 2,
    "max_score": 10,
    "selection_reason": {
      "code": "WEAK_KNOWLEDGE_POINT",
      "message": "该知识点当前掌握度较低",
      "target_difficulty": 2,
      "factors": {
        "mastery_score": 0.3,
        "review_due": false,
        "freshness": 1.0,
        "difficulty_match": 1.0
      }
    }
  }
}
```

当前题目不会返回标准答案、评分点或解析。动态模式找不到下一题时会提前完成，不会重复本轮题目；完全没有可用题目时返回 `409 NO_ACTIVE_QUESTIONS`。

## 3. 查询与恢复会话

`GET /api/study/sessions/{session_id}`

活动会话返回下一道未答题；已完成会话的 `current_question` 为 `null`。接口先以 PostgreSQL 恢复事实状态；若 Redis checkpoint 缺失，会自动重建并设置 TTL。

## 4. 提交答案

`POST /api/study/sessions/{session_id}/answers`

```json
{
  "submission_id": "918b9d92-2424-4dfe-8b6e-047e27b51ed4",
  "question_id": "faadcf55-63af-4430-9326-60be2b8806a6",
  "answer": "A",
  "elapsed_seconds": 8
}
```

答案规则：

- 单选题：提交选项 key，忽略前后空白和字母大小写。
- 填空题：执行全角/半角、大小写、空白和标点规范化后，与任一标准答案精确匹配。
- 判断题：支持布尔值、`1/0`、`true/false`、`正确/错误`、`对/错`。

响应 `200` 的主要字段：

- `verdict`、`score`、`max_score`、`feedback` 和答后可见的 `explanation`。
- `rag_explanation`：包含 `provider`、生成/降级状态、结论、答案差距和真实 chunk 引用。
- `idempotent_replay`：是否为相同提交的重放结果。
- `mastery`：更新后的掌握度、累计答题数、正确数、近期正确率和置信度。
- `review_task`：复习到期时间、间隔、重复次数和 ease factor。
- `session`：更新后的会话统计和下一题；答完时状态自动变为 `completed`。

讲解策略：

- 正确答案直接使用题库解析，`provider=question_bank`，不产生不必要的模型调用。
- 错误答案使用 LangChain `ChatPromptTemplate + PydanticOutputParser` 生成结论和差距。
- 引用由程序从题目绑定的 `question_sources` 附加，模型不能返回或构造引用 ID。
- 模型未配置或调用失败时返回题库解析，状态分别为 `fallback_not_configured` 或 `fallback_model_error`。
- 讲解结果写入 `answer_records.explanation_data`，幂等重放不会再次调用模型。

幂等与失败行为：

- 相同 `submission_id`、会话、题目和答案重复提交：返回原结果，`idempotent_replay=true`。
- 相同 `submission_id` 被不同请求复用：返回 `409 SUBMISSION_ID_CONFLICT`。
- 非当前题提交：返回 `409 QUESTION_OUT_OF_ORDER`。
- 已结束会话首次提交：返回 `409 STUDY_SESSION_FINISHED`。

## 5. 主动结束会话

`POST /api/study/sessions/{session_id}/finish`

无需请求体。活动会话会变为 `completed`；重复调用返回当前已完成状态。

## 6. 查询掌握度

`GET /api/mastery?knowledge_base_id={id}`

返回数组，按掌握度升序排列。初始掌握度基线为 `0.3`：答对后按 `score + 0.15 × (1 - score)` 更新，答错后按 `score × 0.8` 更新。当前算法是可解释的 MVP 基线，不宣称具备教育测量意义。

## 7. 查询到期复习

`GET /api/reviews/due?knowledge_base_id={id}&due_before=2030-01-01T00:00:00Z`

`due_before` 省略时取当前 UTC 时间。返回 `pending` 且到期时间不晚于指定时间的任务。间隔采用简化 SM-2：首次答对 1 天、连续第二次答对 6 天，之后按 ease factor 扩展；答错重置为 1 天。

## 8. 查询学习历史

`GET /api/study/history?knowledge_base_id={id}&page=1&page_size=20`

返回分页会话摘要，不返回题目答案。

## 9. Redis checkpoint

键格式：`study:session:{session_id}:state`。

运行态包含当前题目、已选题目、已答题目、最近五次结果、薄弱知识点、剩余题数和下一动作。Redis 写入失败不会回滚已经提交的数据库事务；缓存缺失时通过查询会话接口从 PostgreSQL 重建。

## 10. 后续预留

- 当确实存在流式讲解需求时再增加 SSE，而不是为短文本讲解提前引入事件系统。
- 主观题开放后新增 LangChain 语义判分链；当前三类客观题继续使用确定性判分。
