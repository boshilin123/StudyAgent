# 知识点与题库接口

## 生成数量与结果

生成请求 `target_question_count` 支持1–100，表示目标数量；不是保证入库数量。结果字段 `generated_count` 表示通过并保存或复用的题数，`rejected_count` 表示本批未接受数量。重复题复用后，知识库题目总数可能不会增加同样数量。保存数量不足目标时新任务标记partial，并给出 `QUESTION_GENERATION_PARTIAL` 与校验拒绝原因；历史任务若曾标completed，前端仍按目标和实际数量判断是否不足。

`GET /api/materials/{material_id}/question-generation-jobs` 返回该资料最近5次任务（最新在前），便于刷新后追踪结果。既有 `GET /api/question-generation-jobs/{id}` 继续可用。

状态：P3 题库生成与题目审核接口已实现；知识点独立管理接口仍为设计稿  
依赖：[接口总览](接口总览.md)

## 1. 查询知识点

`GET /api/knowledge-bases/{id}/knowledge-points`

查询参数：

- `page`、`page_size`。
- `status`：`active` 或 `disabled`。
- `keyword`：名称模糊搜索。
- `sort`：`importance_desc`、`difficulty_asc`、`mastery_asc`。

响应项示例：

```json
{
  "id": "0f437c48-8b99-4d71-a683-c26ca92ddc70",
  "name": "CAP 一致性模型",
  "description": "分布式系统中一致性、可用性和分区容错性的权衡",
  "importance": 0.8,
  "difficulty": 3,
  "status": "active",
  "source_count": 2,
  "question_count": 8,
  "mastery_score": 0.46
}
```

## 2. 更新知识点

`PATCH /api/knowledge-points/{id}`

允许修改：

```json
{
  "name": "CAP 定理",
  "description": "修订后的说明",
  "importance": 0.9,
  "difficulty": 3,
  "status": "active"
}
```

不允许通过接口修改 `knowledge_base_id` 和 `canonical_key`。需要合并知识点时后续增加专用接口，不能通过修改 ID 实现。

## 3. 创建题库生成任务

`POST /api/materials/{id}/question-generation-jobs`

前置条件：资料状态必须为 `ready`，并已建立原文向量。

请求：

```json
{
  "target_question_count": 30,
  "allowed_types": ["single_choice", "fill_blank", "true_false"],
  "difficulty_min": 1,
  "difficulty_max": 4,
  "language": "zh-CN"
}
```

校验：

- `target_question_count`：1–100。
- `allowed_types` 至少一个，值只能为 `single_choice`、`fill_blank`、`true_false`。
- 难度范围为 1–5，起始值不得大于结束值。
- 通过质量门禁的题目仍以 `draft` 保存，必须经过审核接口启用。

响应 `202`：

```json
{
  "id": "2a2ec766-3ec7-4488-9c0c-2023fab11802",
  "material_id": "73976b75-fd18-4892-858d-053008704353",
  "status": "pending",
  "stage": "queued",
  "progress": 0,
  "target_question_count": 30,
  "allowed_types": ["single_choice", "fill_blank", "true_false"],
  "difficulty_min": 1,
  "difficulty_max": 4,
  "language": "zh-CN",
  "generated_count": 0,
  "rejected_count": 0
}
```

## 4. 查询题库生成任务

`GET /api/question-generation-jobs/{id}`

```json
{
  "id": "2a2ec766-3ec7-4488-9c0c-2023fab11802",
  "status": "running",
  "stage": "grounding_validation",
  "progress": 78,
  "statistics": {
    "knowledge_points_extracted": 12,
    "drafts_generated": 27,
    "accepted": 20,
    "rejected": 3,
    "pending_validation": 4
  },
  "run_id": "6bfb4657-67dc-4be8-845a-f50c87ae3708",
  "error": null,
  "started_at": "2026-09-27T09:00:00Z",
  "finished_at": null
}
```

阶段包括 `queued`、`extracting_knowledge_points`、`generating_questions`、`persisting`、`completed` 和 `failed`。结构、来源、难度及批内去重在生成阶段结束后统一执行。

## 5. 查询题目列表

`GET /api/questions`

查询参数：

- `knowledge_base_id`：必填。
- `material_id`、`knowledge_point_id`：可选过滤。
- `question_type`：题型过滤。
- `difficulty_min`、`difficulty_max`。
- `status`：默认不返回 `rejected`。
- `keyword`：题干关键词。
- `page`、`page_size`。

响应项不返回完整来源正文，只返回来源摘要：

```json
{
  "id": "fc47d994-520f-4438-b92e-b0f3acdf6849",
  "knowledge_point": {
    "id": "0f437c48-8b99-4d71-a683-c26ca92ddc70",
    "name": "CAP 定理"
  },
  "question_type": "single_choice",
  "stem": "网络分区发生后，系统拒绝部分请求以维持数据一致性，此时优先保证哪两项？",
  "difficulty": 2,
  "status": "draft",
  "source_count": 1,
  "created_at": "2026-09-27T09:10:00Z"
}
```

  "question_type": "single_choice",

## 7. 更新题目

`PATCH /api/questions/{id}`

允许修改题干、选项、答案、解析和难度。更新后重新执行题型结构校验；来源引用当前只读，避免编辑时构造不存在的片段 ID。

```json
{
  "stem": "发生网络分区时，若系统优先保证一致性，还能同时保证哪一项？",
  "options": [
    {"key": "A", "text": "可用性"},
    {"key": "B", "text": "分区容错性"},
    {"key": "C", "text": "低延迟"},
    {"key": "D", "text": "强扩展性"}
  ],
  "correct_answers": ["B"],
  "explanation": "网络分区已发生时，分区容错性是前提。",
  "difficulty": 2
}
```

已启用题目修改后默认退回 `draft`，需要重新启用，避免未经审核的变更立即进入学习会话。

## 8. 启用题目

`POST /api/questions/{id}/activate`

服务端重新检查：Schema、选项结构、答案、评分点、来源、知识点归属和状态。通过返回更新后的题目；失败返回 `422 QUESTION_QUALITY_GATE_FAILED`，`details` 给出失败规则列表。

## 9. 停用题目

`POST /api/questions/{id}/disable`

可选请求：

```json
{
  "reason": "答案存在歧义"
}
```

停用不会删除历史答题记录。已创建的模拟考试若包含该题，应继续使用会话快照；其他模式不再选取。

## 10. 删除题目

`DELETE /api/questions/{id}`：返回 `204`，重复删除同样返回 `204`。

将题目标记为 `deleted` 并清理检索向量。题库列表、数量统计和新学习选题排除该题；详情、编辑、启用和停用接口返回 `404`。题目行、原文来源和历史作答保留，历史作答的幂等重放与已答题辅导仍可使用。未答题若被删除，提交返回 `409 QUESTION_UNAVAILABLE`，需结束本轮学习。重新生成相同内容不会自动恢复已删除的题目。

如果索引清理失败，题目仍已退出题库，接口返回 `503 QUESTION_DELETE_INDEX_PENDING`，再次删除可重试索引清理。

## 11. 生成时拒绝的候选题

生成任务详情及资料的生成历史接口新增 `rejected_candidates` 数组，每项包含 `reason` 与模型返回的 `question`（题干、题型、选项、候选答案、解析、难度、来源片段 ID 和引文）。未通过校验的候选题保留在任务记录中，不入题库，不参与学习，也不计入知识库题目数量。

该数组与题库中的 `rejected` 状态分开：前者是生成门禁失败记录，后者是已入库题目的状态。上线前的历史任务数组为空，只能查看当时已经记录的拒绝数量和错误消息，不能还原未保存的候选题内容。
