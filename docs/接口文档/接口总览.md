# StudyAgent 接口总览

状态：P0–P6 已实现，前端已接入本文档列出的真实接口  
适用范围：单用户 MVP  
基础路径：`/api`

## 1. 通用约定

### 1.1 数据格式

- 除文件上传和 SSE 外，请求与响应均使用 `application/json; charset=utf-8`。
- 文件上传使用 `multipart/form-data`。
- 时间使用 ISO 8601 UTC，例如 `2026-09-27T08:30:00Z`。
- 资源 ID 使用 UUID 字符串。
- JSON 字段使用 `snake_case`。
- 列表默认按创建时间倒序，分页使用 `page` 与 `page_size`。

### 1.2 成功响应

单资源直接返回资源对象，列表返回统一分页结构：

```json
{
  "items": [],
  "page": 1,
  "page_size": 20,
  "total": 0
}
```

创建资源通常返回 `201 Created`，查询和更新返回 `200 OK`，异步任务创建返回 `202 Accepted`，成功删除返回 `204 No Content`。

### 1.3 错误响应

```json
{
  "error": {
    "code": "QUESTION_NOT_FOUND",
    "message": "题目不存在或已删除",
    "details": {},
    "request_id": "01K6..."
  }
}
```

常用状态码：

- `400`：请求语义错误。
- `401`：访问令牌缺失或不匹配。
- `404`：资源不存在。
- `409`：状态冲突或幂等键冲突。
- `422`：字段校验失败。
- `429`：请求或模型调用频率超限。
- `500`：未处理的服务端错误。
- `503`：模型、向量库或对象存储暂时不可用。

错误码保持稳定，中文 `message` 可以优化但前端不能依赖文案判断逻辑。

### 1.4 幂等

- 创建资料使用可选请求头 `Idempotency-Key`。
- 提交答案必须携带客户端生成的 `submission_id`。
- Celery 任务以业务资源 ID 和阶段组成幂等键。
- 同一幂等键与相同请求体重复提交时返回原结果；请求体不同则返回 `409 IDEMPOTENCY_CONFLICT`。

### 1.5 单用户边界

MVP 不提供注册、登录、租户、角色和权限接口。开发编排端口仅绑定本机。设置 `API_ACCESS_TOKEN` 后，业务接口要求 `Authorization: Bearer <token>`，令牌至少 32 位且仅含 URL-safe 字符；生产环境强制设置。前端右上角可录入令牌，仅存于当前标签页的 `sessionStorage`。`/api/health/live`、`/api/health/ready` 与 CORS 预检不要求令牌。

就绪检查探测 PostgreSQL、Redis、Broker、Milvus 与存储；全部成功返回 `200`，任一失败或超时返回 `503`，不向调用者暴露连接串或异常详情。该门禁不提供资源所有权隔离；未来增加账号时需继续扩展 `owner_id`。

## 3. 状态枚举

### 3.1 资料处理状态

```text
uploaded → parsing → parsed → chunking → embedding → ready
                └→ failed
```

资料的 `parse_status` 表示总体处理状态；具体阶段、进度和错误读取 `ingestion_job`。

### 3.2 异步任务状态

- `pending`：已创建，尚未执行。
- `running`：正在执行。
- `partial`：部分章节成功。
- `completed`：全部完成。
- `failed`：失败且没有可用结果。
- `cancelled`：预留，MVP 可不提供取消接口。

### 3.3 题目状态

- `draft`：自动生成或人工创建，尚未启用。
- `active`：可以进入学习会话。
- `disabled`：人工停用。
- `rejected`：未通过质量门禁。

### 3.4 学习会话状态

- `active`：可以继续答题。
- `completed`：正常结束。
- `abandoned`：用户主动结束或长期未完成。
- `failed`：不可恢复的系统错误。

## 4. SSE 约定（P5 预留，尚未实现）

`GET /api/study/sessions/{id}/events` 使用 `text/event-stream`，支持：

- `session.started`
- `question.ready`
- `grading.started`
- `grading.completed`
- `explanation.delta`
- `explanation.completed`
- `session.completed`
- `error`
- `heartbeat`

事件示例：

```text
id: 42
event: grading.completed
data: {"session_id":"...","question_id":"...","verdict":"partial","score":6,"max_score":10}

```

客户端使用 `Last-Event-ID` 重连。SSE 只负责通知和增量文本，最终状态必须通过普通 GET 接口确认。

## 5. 可观测性

- 服务端为每次请求生成或透传 `X-Request-ID`。
- 异步任务响应包含 `job_id`。
- LLM/RAG 执行响应可包含 `run_id`，用于定位 Trace。
- 日志不得输出模型密钥、上传文件原文、完整 Prompt 或完整用户答案。

## 6. 版本策略

MVP 暂不在 URL 中加入 `/v1`。出现不兼容修改时再引入 `/api/v1`；在此之前通过新增可选字段保持向后兼容。删除字段前至少经过“标记弃用 → 前端迁移 → 删除”三个阶段。
