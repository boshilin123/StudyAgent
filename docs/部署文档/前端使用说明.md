# StudyAgent 前端使用说明

## 1. 访问地址

使用 Docker Compose 启动后访问 <http://localhost:55173>。前端默认通过 Vite 代理访问 `/api`，本地不需要额外配置 API 地址。

页面包括：首页、知识库、题库、开始学习、学习进度。

## 2. 推荐操作顺序

1. 在“知识库”创建个人知识库。
2. 上传 PDF、DOCX、PPTX、TXT、Markdown 或结构化 XLSX 资料。
3. 等待资料处理进度达到 100%，失败时查看页面错误信息和处理阶段。
4. 从已完成的资料创建题库生成任务。
5. 在“题库”核对题干、答案、解析和原文来源，再启用合格题目。
6. 在“开始学习”选择知识库、模式、题型和难度后开始作答。
7. 作答后查看判题结果、讲解和原文引用；在“学习进度”查看掌握度、复习计划和历史。

## 3. 会话恢复

前端把当前活动会话 ID 保存在浏览器本地存储中。刷新或重新打开学习页面时，会调用后端会话详情接口恢复当前题目和进度。Redis checkpoint 丢失时，后端会使用 PostgreSQL 中的事实数据重建状态。

会话已经完成、主动结束或后端确认不存在时，本地活动会话会被清理，页面回到学习设置。

## 4. 页面功能边界

- 当前题型仅包含单选、填空和判断题，均由确定性规则判分。
- 错题可以触发 LangChain 引用讲解；正确题直接返回题库解析，避免不必要的模型调用。
- 当前讲解使用普通 HTTP 响应，不使用 SSE；只有真实长文本流式需求出现时再增加流式协议。
- 题目默认以草稿保存，需要人工核对来源后启用，学习工作台只选择已启用题目。
- 项目是单用户个人学习工具，不包含账号、组织、分组和权限管理。

## 5. 常见问题

### 页面没有可选知识库

先在“知识库”创建至少一个未归档知识库。

### 开始学习时提示没有可用题目

确认该知识库至少有一道已启用题目，并检查题型、难度筛选是否过窄。复习模式还要求存在到期复习任务。

### 上传后长时间没有进度

执行 `docker compose ps` 检查 API、Worker、Redis、Milvus 和对象存储是否运行，再通过处理任务接口或容器日志定位具体阶段。

### 刷新后没有恢复会话

浏览器本地存储可能已清理，或者会话已经完成。可在“学习进度”的历史记录中确认会话状态，然后重新开始学习。

## 6. 前端开发检查

```powershell
Set-Location apps/web
npm.cmd run typecheck
npm.cmd run build
```

Compose 环境可使用：

```powershell
docker compose exec web npm run typecheck
docker compose exec web npm run build
```
