# 后端来源出题与学习注释

2026-10-09：按个人使用和简历展示的定位实施方案 B。

## 出题流程

1. 从非空原文片段中最多选三组，每组最多四个片段；长资料按前、中、后部选取，不代表全文覆盖。
2. 三组上下文的总长度受 `QUESTION_GENERATION_MAX_CONTEXT_CHARS` 控制。被截断的片段只绑定实际输入部分。
3. 每组先提取知识点，再根据该组知识点和原文生成题目。模型不需要输出片段 UUID 或逐字引文。
4. 后端绑定本组真实片段 ID 和实际输入原文，校验题型、难度、知识点及重复内容。
5. 数量不足时最多补充一次，并提供已有题干；补充失败仍保存首轮有效题目。超额有效题正常截取，不计入拒绝。
6. 保存为待审核草稿并建立题库向量索引，用户核对答案后启用。

来源使用 `source_kind=reference_context`；兼容字段 `quote` 保存出题上下文。旧来源默认 `source_kind=quote`，原文引文保留；复用旧题时不会覆盖已有的旧引文。接口同时返回资料名称、页码和标题路径，题库与练习页面可展开查看。

基础校验不等于答案语义审核。此次调整取消了引文数量配对和逐字匹配造成的拒绝，辅导 Agent 的独立引用校验仍保留。

任务进度仍是阶段值：0 等待、10 提取知识点、45 生成题目、75 保存和索引、100 处理结束。`partial` 也会到 100，不表示目标数量全部达成。

## 验证方式

- 离线回归、Ruff、Mypy 与前端编译。
- `scripts/prepare_upgrade_test_database.py`：仅在固定测试数据库执行迁移和事务回归。
- Playwright：检查参考原文展开、资料页码、新上下文与旧引文展示，以及旧拒绝详情兼容性。
- `scripts/验证后端来源出题.py`：默认使用自编合成资料、真实模型和独立向量集合生成十题，再验证来源、审核、练习和复习更新。测试资源自动清理，报告写入 `apps/api/tmp/scheme_b_live_report.json`。

真实验收脚本须在 Docker API 容器执行，默认不会读取正式资料。只有明确授权后才使用 `--user-pdf` 读取第1章 PDF。正式题库不因验收增加题目；既有拒绝记录也不会自动变成新题。

数据库新增迁移 `0009`，给来源表添加类型字段，不删除已有题目和引文。

本次验证结果：离线回归 153 项通过，隔离 PostgreSQL 回归 27 项通过，Ruff、Mypy（79 个源文件）和前端编译通过。浏览器首轮 34 项通过、1 项可选外部验收跳过；修正测试拦截范围并适配原文展开交互后，9 项相关回归全部通过。合成资料的真实 `deepseek-flash` 验收生成 10 题、拒绝 0 题，来源、向量入库、审核、练习与复习更新通过，测试资源已清理。这一结果不保证其他资料的题目数量或答案正确性。
