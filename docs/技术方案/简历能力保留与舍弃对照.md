# 简历能力保留与舍弃对照

状态：初稿  
目的：说明企业项目中的技术亮点在个人版中哪些保留、调整、暂缓或删除，避免改造范围和最终简历表述不一致。

## 1. 技术栈变化

### 保留

- Python、FastAPI、Qwen、LangChain。
- Milvus：继续作为原文索引和题库索引的向量数据库。
- Redis：Celery Broker、任务状态、学习会话状态和超时控制。
- Celery：资料解析、向量化和题库生成任务。
- MinIO：原始资料对象存储。
- Docker Compose：本地和演示环境编排。

### 替换

- MySQL 替换为 PostgreSQL。原因不是必须依赖 PostgreSQL 的特殊能力，而是新项目会彻底重建数据模型，使用 PostgreSQL + SQLAlchemy + Alembic 更适合统一业务数据、JSON 结构化字段、约束和 Agent Trace。

### 删除

- MongoDB。旧系统主要用它保存答题过程日志；个人版将答题记录、会话摘要和 Agent Trace 统一保存到 PostgreSQL，避免为了单一日志用途多维护一个数据库。
- pgvector。它曾作为“用一个数据库替换 PostgreSQL + Milvus 两套组件”的轻量方案，但最终决定保留 Milvus，以延续现有题库型 RAG 和元数据过滤能力。

改造后的预期技术栈为：

```text
Python、FastAPI、Qwen、LangChain、PostgreSQL、Milvus、
Redis、Celery、MinIO、Vue 3、Docker Compose
```

## 2. 原简历条目对照

### 2.1 智能题库生成

结论：保留并重构，是个人版核心能力。

保留：

- PDF、Word、Excel 等资料解析。
- 知识点提取、填空题和问答题生成。
- 标准答案、章节、页码、原文位置和难度元数据。
- 多阶段生成和结构化 JSON 输出。

调整：

- 将“题库生成 Agent”改称“基于 RAG 的题库生成工作流”。
- 先将资料块写入 Milvus，再由 Retriever 按章节或知识点召回原文，作为题目生成证据。
- 增加 `source_chunk_ids`、引用原文匹配、Schema 校验和质量门禁。
- “背景生成”不再作为必经步骤。优先直接使用原文片段和邻接上下文，只有原文过于碎片化时才生成受约束的上下文摘要。

### 2.2 异步数据处理

结论：保留，是资料处理链路的必要能力。

保留：

- Celery Chain/Group。
- Redis 任务状态和进度。
- 并发限制、失败重试、结构化解析和题目去重。

删除或简化：

- 企业文件类型对应的大量专用分支。
- 与 SOP 版本、岗位和第三方状态同步有关的任务。
- 无明确价值的重复 Celery 任务封装。

### 2.3 题库型 RAG

结论：保留，是区别于普通文档问答项目的重要能力。

保留：

- Milvus 题干向量及标准答案、题型、难度、知识点和来源 metadata。
- metadata 过滤、历史题目排除和难度筛选。
- 相似题去重和错题相关题召回。

调整：

- 增加独立的原始资料索引，形成原文索引 + 题库索引的双索引设计。
- 初始随机抽题不再使用随机 `session_id` 作为向量 Query。
- 模拟考试使用过滤后随机采样；自适应练习使用薄弱知识点和错题构造 Query。

暂缓：

- LLM Rerank 不作为第一条链路的硬依赖。先完成向量召回、metadata 过滤和可复现评测；确有提升后再启用，并在简历中使用真实评测结果。

### 2.4 自适应学习 Agent

结论：保留并升级，是个人版的另一项核心能力。

保留：

- Redis 状态机。
- 学习进度、历史题目、错题记录和追问状态。
- 正常出题与错题追问分支。
- 同知识范围检索与难度递进。

新增：

- 知识点掌握度。
- 诊断、练习、复习和模拟考试模式。
- SM-2 间隔复习。
- 明确的选题评分公式和选择原因。

暂不加入：

- LangGraph。MVP 使用 Python + Redis 显式状态机，LangChain 负责 Retriever、判题 Chain 和讲解 Chain。等现有流程稳定并确实需要 checkpoint 图编排时再引入。
- 多 Agent 协作。

### 2.5 LLM 语义判分

结论：完整保留并加强可靠性。

保留：

- 填空题精确匹配快速路径。
- 问答题的语义评分、评分点覆盖、部分得分和错因分析。
- 差异化 Prompt。

新增：

- LangChain Structured Output + Pydantic Schema。
- 程序化分数钳制和 verdict 重算。
- 模型失败时标记 `grading_failed`，不再默认为答错。
- 低置信度判题进入人工复核或降低掌握度更新权重。

### 2.6 会话与数据架构

结论：会话能力保留，数据库分层简化。

保留：

- 多轮 `/start → /answer → /finish` 业务语义。
- Redis 会话、计时、幂等控制和超时结束。
- SSE 流式反馈。
- 运行状态与长期数据分离的设计思想。

调整：

- API 资源化为 `/study/sessions` 和 `/study/sessions/{id}/answers`，不保留旧兼容接口。
- PostgreSQL 保存资料、题目、学习会话、答题记录、掌握度、复习任务和 Agent Trace。
- Milvus 只保存检索所需的向量与最小 metadata。

删除：

- MongoDB 答题日志库。
- MySQL 旧企业表及散落的手写 SQL。
- 企业成绩表、排行榜和第三方推送记录。

### 2.7 模型与部署工程化

结论：保留接口抽象和容器化，删掉企业级部署负担。

保留：

- OpenAI-compatible LLM。
- LangChain Embeddings 接口。
- TEI、OVMS 等 Embedding 后端适配能力；只迁移实际可运行的适配器。
- Docker Compose。

MVP 简化：

- 模型配置先使用 `.env`，暂不迁移数据库动态配置页面。
- Compose 只编排 Web、API、Worker、PostgreSQL、Milvus、Redis、MinIO。

删除：

- Kubernetes、Helm、HPU/GPU 多套部署模板。
- 企业镜像仓库和固定公网地址。
- Dify 插件、MCP、Web Search 等与学习闭环无关的组件。

## 3. 原项目中整体删除的能力

- 账号注册、登录、租户、用户组、角色和权限。
- 公司、部门、岗位和组织树。
- License 管理。
- SOP 企业术语、生效期、版本和岗位混合出题。
- 公告、排行榜、部门完成率、用户活跃率和心跳。
- 视频课程、视频进度、ASR/TTS 和语音陪练。
- 第三方企业系统成绩推送。
- MongoDB、Kubernetes、Helm、Dify 插件、MCP 和 Web Search。

## 4. 简历稿需要修改的地方

当前提供的简历稿不能原样作为“个人项目改造完成后”的版本，至少需要修改：

1. 技术栈中的 `MongoDB、MySQL` 改为 `PostgreSQL`。
2. 题库生成描述补充 LangChain Retriever、结构化输出和引用验证。
3. “题库生成 Agent”使用“题库生成 RAG 工作流”更准确。
4. LLM Rerank 只有实际保留、完成评测后才能继续写。
5. 动态模型配置只有迁移完成后才能写；MVP 若仅使用 `.env`，应写成“可插拔模型适配层”。
6. 不能写 LangGraph、混合检索或量化性能，直到代码和评测真实完成。

最终简历应以完成后的代码和评测为准，本文件只作为改造过程中的能力对照，不是最终简历。
