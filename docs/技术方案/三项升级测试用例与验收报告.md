# 三项升级测试用例与验收报告

日期：2026-10-01（Asia/Shanghai）。验收主体：第四个独立 `upgrade-acceptance` subagent。

## 执行约束与证据口径

此报告先冻结测试输入和预期，只有 root 明确「整合完成」后才开始最终整体验收。前三个实施者的历史通过结果是交接资料，不作为本报告最终通过证据。实现故障交责任实施者修复，验收者不降低预期以配合实现。

隔离 PostgreSQL 数据库为 `study_agent_test_upgrade`，测试代码必须校验数据库名前缀。不删除或迁移业务数据库、不重启或替换业务容器、不删除卷、不提交或推送。数据库/模型连接从现有配置内部读取，不在命令输出或报告中写密码、令牌、完整连接串。

证据分成四类：真实 LangChain 图＋脚本化模型；真实 PostgreSQL/Milvus/Redis；真实 Chrome＋HTTP fixture；真实模型供应商。浏览器 fixture 不证明后端正确，脚本化模型不证明真实模型兼容，结构引用验证不证明语义忠实。40条人工质量集只有独立人工标注后才能计算质量门槛。

优先级：P0 为范围、幂等、持久化与原有学习事实保护；P1 为必需交互及可控错误；P2 为质量与对照测量。状态初值为待执行；失败、跳过、待人工分别记录，不计为通过。所有案例使用独立随机实体ID；显式锚点是数据库真实已作答记录，不能只在请求中声称已作答。

## 固定测试资料

KB-A：网络主题，ready资料 `TCP资料`，正文「三次握手用于确认双方收发能力」，第2页，版本哈希A。KB-B：同主题但不同正文「B库私有资料」，仅属于B。各自有chunk/material/source。
