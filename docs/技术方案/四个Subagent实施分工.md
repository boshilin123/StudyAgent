# 四个 Subagent 实施分工

日期：2026-10-01。用户已明确授权执行三项升级及整体代码完成后的独立验收。

## 角色与文件边界

1. `langchain-v1-upgrade`：依赖清理与 v1 锁定、统一模型工厂、供应商兼容、原出题与讲解链迁移。拥有 pyproject、两个锁文件、llm、config、chains、study_explanations。
2. `naming-alignment`：Chain/Agent、Context/State、学习快照与工作流轨迹命名对齐、调用方迁移、课程源码导读。拥有原有领域端口、ORM/repository、学习服务、快照与相关测试；数据库物理名称、Redis key 与 HTTP 契约保持兼容。
3. `tutor-agent-upgrade`：真正的单辅导 Agent、四个只读工具、证据校验、调用预算、会话/轮次/检查点持久化及 API。新增辅导模块和独立 ORM 文件，避免和第二项冲突。
4. `upgrade-acceptance`：独立设计与执行详细测试，在三项代码及根协调集成完成后给出整体结论。覆盖依赖、命名、原功能、工具循环、引用、权限、数据库并发/重启、浏览器恢复与真实模型证据。

持久角色定义位于项目 `.cursor/agents/`。根协调负责文件冲突、Vue 辅导页面与答后入口、后端生命周期/路由、环境和验收失败的修复分派，不替代第四角色的最终验收。

## 执行顺序

三项升级同时开始探索和各自独占模块实现；统一模型工厂和命名接口尽早发布。因当前并发槽位限制，第四角色在先完成的工作角色交接后启动，先建立测试清单，待所有代码完成后运行最终完整验收。

验收发现缺陷后由对应工作角色修复，第四角色复跑相关失败场景，并核对完整集成结果。测试报告必须区分实际通过、失败、未执行/跳过，特别区分 Fake Model、真实数据库、HTTP/browser mock 与真实供应商调用。

## 交付与约束

- 修改可审阅的源码、依赖锁、数据库迁移、页面与源码导读。
- 新增详细测试用例及验收报告，每例包含前置条件、输入步骤、预期结果、实际结果和证据。
- 使用独立且明确命名的 `study_agent_test*` 数据库；不清理业务库或存储卷。
- 不自动提交、推送、发布；不打印密钥或完整 `.env`。
- 真实模型不可用时说明原因并保留可运行脚本，不把离线模型结果冒充真实模型通过。
