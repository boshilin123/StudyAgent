# StudyAgent 测试与验收方案

状态：P7 第一版评测基线已落地

## 1. 测试目标

- 验证资料、题目、学习记录和复习计划不会因重试或异常产生重复、丢失或错配。
- 将确定性业务规则与非确定性模型能力分开测试。
- 用固定评测集判断 RAG、生成和判题质量，不以单次演示结果代替评测。
- 所有简历量化数据都必须能由脚本和结果文件复现。

## 2. 测试分层

### 单元测试

不连接外部服务，重点覆盖：

- 文件类型、大小、哈希和 metadata 校验。
- 文本切块边界、页码与标题继承。
- 三类题目的 Pydantic Schema。
- 单选、填空快速判分和分数钳制。
- 知识点优先级与题目优先级。
- 掌握度更新和 SM-2。
- 会话状态迁移、超时和 `submission_id` 幂等。
- Agent 工具输入输出校验。

领域层单元测试覆盖率目标不低于 80%，但验收以关键规则全部覆盖为优先。

### 集成测试

使用容器化 PostgreSQL、Redis、Milvus 和 MinIO：

- Alembic 从空库升级到最新版本。
- Repository 查询、约束和事务回滚。
- 文件上传、对象删除和失败补偿。
- Milvus upsert、过滤、删除和稳定 ID。
- Celery 成功、重试、部分失败和幂等。
- Redis 会话恢复和过期。

LLM 默认使用固定 Stub；另设显式标记的真实模型集成测试，避免普通 CI 产生费用和波动。

### API 契约测试

- 状态码、响应 Schema 和错误码。
- 分页边界和非法查询参数。
- 上传类型和大小限制。
- 重复提交与状态冲突。
- 当前短响应讲解的响应结构；确有流式需求并引入 SSE 后再测试事件格式、心跳和重连。
- 活动题目的答案不在出题响应中泄露。

### 端到端测试

最小主链路：

```text
创建知识库
→ 上传固定 PDF
→ 等待解析和向量化
→ 生成题目
→ 人工启用题目
→ 开始练习
→ 回答三种题型
→ 查看总结、掌握度和到期复习
```

端到端测试使用专门的小型文档夹具，不使用个人敏感资料。

## 3. LLM 与 RAG 评测

### 检索评测集

每条样本至少包含：查询、知识库、相关 chunk IDs 和人工说明。指标：

- Hit@1、Hit@3、Hit@5。
- Recall@5。
- MRR。
- P50、P95 检索耗时。

先记录 Dense Retrieval 基线。只有新策略在相同集合上稳定提升，才加入默认链路。

### 题库生成评测集

从不同文件类型和章节结构中选取固定资料，人工审核：

- Schema 合法率。
- 来源可验证率。
- 答案被原文支持的比例。
- 重复率。
- 人工审核通过率。
- 知识点覆盖情况。

模型生成的题目不能直接作为评测真值。

### 简答题判分评测集

每道题准备标准答案、评分点和多档人工回答，至少覆盖正确、部分正确、错误、答非所问和空答案。由两人或同一规则下的复核结果形成标签。

记录：

- verdict 一致率。
- 分数平均绝对误差。
- 低置信度样本覆盖率。
- `grading_failed` 比率。
- 不同 Prompt/模型版本的差异。

## 4. 核心验收用例

### 资料处理

- 正常 PDF 能完成解析、切块、向量化。
- 加密、空白、损坏和超大文件返回明确错误。
- 同一文件重复上传不会产生重复对象和片段。
- 单页失败时任务可标记 partial，成功页结果可用。

### 题库生成

- 每道启用题至少关联一个真实 chunk。
- 引文不存在、答案为空、选项重复或评分点为空的题不能启用。
- 同一生成任务重试不产生重复题目。
- 修复超过两次后拒绝，不能无限循环。

### 学习会话

- 同一 `submission_id` 重复请求只产生一条答题记录。
- 非当前题目不能提交。
- LLM 判题失败不更新掌握度和复习时间。
- 成功提交时四项业务写入处于同一事务。
- 模拟考试开始后题目集合和顺序保持不变。
- 会话中断后从 Redis checkpoint 恢复，并重新读取数据库事实。

### 安全与隐私

- 仓库和镜像中没有真实密钥。
- 日志不输出上传全文、完整 Prompt 和数据库密码。
- 文件名不能造成路径穿越。
- Markdown 讲解经过 XSS 清洗。
- MinIO 对象默认不公开访问。

## 5. 测试数据和模型版本

- 测试夹具进入 `tests/fixtures`，注明来源和许可。
- 评测集进入独立目录，人工标签与模型输出分开保存。
- 每次结果记录 Git commit、模型、Embedding、Prompt、切块参数和索引参数。
- 真实模型测试由环境变量显式开启，默认跳过。
- 禁止在测试代码中硬编码 API Key。

## 6. 发布门禁

发布候选版本必须满足：

- 数据库迁移、单元、集成和 API 契约测试全部通过。
- 主链路端到端测试通过。
- 无高危依赖和明文 Secret。
- 新增模型链已在固定评测集运行并保存结果。
- Docker Compose 可从空数据卷启动。
- 部署、接口和变更说明已更新。

## 7. 简历数据门禁

以下数据只有在测试脚本、输入集合和结果文件均保存后才能写入简历：

- 单份资料平均生成题目数与人工审核通过率。
- 资料处理耗时变化。
- LLM 判题与人工评分一致率。
- Recall@5 和 Rerank 提升。
- 并发会话数和接口 P95。

没有真实结果时只描述设计和实现，不填估算数字。
