# StudyAgent 个人项目最小化改造方案

状态：初稿  
适用阶段：旧项目拆解、新项目骨架设计、MVP 实现  
来源项目：`D:\BlueDot\BEAT陪练\eap`、`D:\BlueDot\BEAT陪练\eap-chat`

## 1. 决策摘要

StudyAgent 不从旧项目做“全量去企业化”，而是在新仓库中实现一个面向单个学习者的最小学习闭环，并从旧项目按能力白名单迁移代码。

MVP 只验证下面这条主链路：

```text
创建知识库
  → 上传资料
  → 解析、切块并抽取知识点
  → 生成可溯源题库
  → 进行诊断或练习
  → 记录答题结果并更新掌握度
  → 安排间隔复习
  → 查看本次总结和待复习任务
```

这条链路之外的功能，默认不迁移；只有能够直接提升这条闭环质量的功能，才允许进入 MVP。

## 2. 产品边界

### 2.1 MVP 用户

第一版是单用户个人项目，默认运行者就是唯一学习者。因此：

- 不提供注册、登录、找回密码和第三方登录。
- 不提供租户、用户组、角色和权限配置。
- 不提供管理员后台。
- 不在业务表中传播 `tenant_id`、`company_id`、`department_id`、`position_id`。
- 数据库仍使用清晰的资源主键和关联关系，未来需要多用户时再引入 `owner_id`。

### 2.2 MVP 学习场景

第一版支持：

- 创建一个学习主题或知识库。
- 上传 PDF、DOCX、PPTX、TXT/Markdown；Excel 只保留结构清晰的问答表导入。
- 从资料中抽取知识点并生成问答题、填空题或单选题。
- 对生成题目进行查看、编辑、启用和停用。
- 开展诊断、普通练习、到期复习和模拟考试。
- 对答案评分、解释错误，并引用原始资料。
- 按知识点维护掌握度，并用 SM-2 安排复习。
- 查看知识点掌握情况、本次学习总结和到期任务。

第一版不支持：

- 企业培训计划、组织分发和完成率考核。
- 多人排名、部门排名和企业看板。
- 岗位混合出题、SOP 生效期和企业版本管理。
- 视频课程、ASR/TTS、实时语音陪练。
- 多语言完整本地化。
- 多 Agent 互相协作。
- Kubernetes、Helm、多机推理和复杂监控平台。
- 第三方企业系统成绩推送。

## 3. 保留白名单

迁移不是复制目录。每一项都必须先抽离企业字段、硬编码地址和旧基础设施依赖，再进入新仓库。

### 3.1 后端保留

#### 文档解析能力

来源参考：旧 `dataprep` 组件。

保留：

- 文件类型识别。
- PDF、Word、PPT、纯文本解析。
- OCR 的可选降级路径。
- 标题感知切块、页码和标题路径提取。
- 后台任务及任务进度查询思路。
- 文档解析失败重试与错误记录。

迁移时重写：

- 输入输出模型。
- 与 SOP、岗位、租户相关的参数和 SQL。
- Milvus 写入与过滤检索思路，但改为统一的向量存储接口并重建集合 Schema。
- 大量文件类型专用 Prompt，先收敛到通用学习资料。

#### 题目生成能力

来源参考：旧 `dataprep/service`、Prompt 和去重逻辑。

保留：

- 基于原文片段生成题目。
- 批量生成、去重、重试和人工修订思路。
- 题型、难度、标准答案、解析等字段。

必须新增：

- 知识点归属。
- `source_chunk_ids` 和引用位置。
- 结构化输出校验。
- 答案必须被原文支持的质量门禁。
- 生成批次与 Prompt/模型版本追踪。

#### 学习会话能力

来源参考：旧 `smart_practice`。

保留：

- Redis 会话和断点恢复思路。
- SSE 流式响应。
- 判题、错因解释和相似题追问思路。
- 考试结束时汇总本轮记录。

迁移时重写：

- `/start → /answer → /finish` 的考试专用状态机。
- 以随机 `session_id` 做向量 Query 的初始抽题方式。
- SOP/岗位范围过滤和企业成绩推送。
- 只保存错题列表、不维护长期掌握度的状态模型。
- LLM JSON 正则兜底和未经边界校验的分数处理。

#### 基础能力

选择性保留：

- OpenAI-compatible 模型调用封装。
- Embedding 后端抽象。
- Markdown 渲染与引用展示所需协议。
- 日志、Trace ID、Token 用量和模型耗时记录。

暂不迁移数据库动态模型配置。MVP 用 `.env` 管理 LLM、Embedding 和数据库配置，等核心闭环稳定后再增加设置页面。

### 3.2 前端保留

来源参考：旧 Vue 3 前端。

可复用：

- Vue 3、Vite、TypeScript、Pinia、Vue Router 和 Element Plus 技术栈。
- 文件上传、进度显示和文件预览组件。
- Markdown 渲染器。
- SSE/Fetch 流式读取模式。
- 基础布局、错误提示和请求封装思路。

只参考交互、不直接搬运：

- `ChatExam.vue` 的对话式答题体验。
- 素材库、课程列表和题目复核页面。
- 仪表盘中的热力图和统计卡片。

必须重写：

- 路由和导航信息架构。
- 登录、用户、公司、部门、岗位、License、模型管理页面。
- 企业仪表盘和排行榜。
- 超过千行的页面组件，按页面容器、业务组件和 composable 拆分。
- 多套 Axios 实例和重复的 Token 拦截器。

## 4. 明确舍弃清单

以下内容不得因为“旧系统已经有”而默认迁移：

### 4.1 业务功能

- 账号注册与企业用户管理。
- 租户、公司、部门、岗位和组织树。
- 角色、菜单和细粒度权限。
- License 注册和授权管理。
- SOP 专属命名、生效期、企业版本和岗位混合考试。
- 企业公告、部门完成率、排行榜和资源总览。
- 东方希望或其他企业适配接口。
- 在线时长、用户心跳和活跃率统计。
- 视频课程、视频进度、ASR/TTS 和移动端语音输入。
- Web Search、天气 MCP、Dify 插件等非核心组件。

### 4.2 技术设施

- 旧 `.git` 历史和远端地址。
- OPEA 通用网关中与本项目无关的能力。
- MongoDB 聊天历史服务；答题日志、Agent Trace 和会话摘要统一进入 PostgreSQL。
- 旧 MySQL 表结构和散落在各组件中的手写 SQL；关系数据改用 PostgreSQL + SQLAlchemy + Alembic。
- Kubernetes、Helm、HPU/GPU 多套推理部署。
- 旧镜像仓库、固定公网 IP、默认账号和默认密码。

## 5. 目标技术架构

MVP 采用模块化单体，而不是复刻旧微服务：

```text
┌──────────────── Vue 3 Web ────────────────┐
│ 知识库 │ 资料与题库 │ 学习工作台 │ 复习与进度 │
└──────────────────┬────────────────────────┘
                   │ HTTP + SSE
┌──────────────────▼────────────────────────┐
│                FastAPI API                 │
│ knowledge │ ingestion │ question │ study   │
│ mastery   │ review    │ tutor    │ settings │
└───────────────┬────────────────┬────────────┘
                │                │
       ┌────────▼────────┐ ┌─────▼───────────┐
       │ Celery Worker     │ │ Learning Agent  │
       │ 解析/RAG/生成题库 │ │ 选题/判题/讲解   │
       └────────┬────────┘ └─────┬───────────┘
                │                │
┌───────────────▼────────────────▼─────────────┐
│ PostgreSQL │ Milvus │ Redis │ MinIO          │
└───────────────────────────────────────────────┘
```

建议技术选型：

- 前端：Vue 3 + Vite + TypeScript + Pinia + Element Plus。
- API：Python 3.12 + FastAPI + Pydantic v2 + SQLAlchemy 2。
- 关系数据库：PostgreSQL 16。
- 向量数据库：Milvus，分别保存原始资料向量和题库向量。
- 迁移工具：Alembic。
- 后台任务：Celery + Redis，资料解析、向量化和题库生成使用 Celery Chain/Group。
- LLM/RAG 框架：LangChain，统一 Document、Splitter、Embedding、Milvus VectorStore、Retriever、Prompt、Structured Output 和 Runnable 编排。
- 学习编排：MVP 使用显式 Python + Redis 状态机，并通过 LangChain 调用检索、判题和讲解链；LangGraph 只作为后续可选升级，不写入当前实现能力。
- 文件存储：MinIO；本地测试可通过同一 `Storage` 接口切换到文件目录。
- 测试：pytest、pytest-asyncio、Vitest；Agent 工具与状态迁移必须有单测。

这里不采用 PostgreSQL + pgvector 替代 Milvus。pgvector 的优势是部署更轻、关系查询与向量查询共用一个数据库，但现有项目的重要可复用资产正是 Milvus 元数据过滤、题库召回和难度筛选。保留 Milvus更能延续题库型 RAG 能力，也便于分别管理原文索引和题库索引。为了控制复杂度，删除 MongoDB，并由 PostgreSQL 统一承担业务数据、会话摘要和 Agent Trace；最终只保留 PostgreSQL、Milvus、Redis、MinIO 四个基础组件。

## 6. 建议代码结构

```text
StudyAgent/
├── apps/
│   ├── api/
│   │   ├── study_agent/
│   │   │   ├── api/
│   │   │   ├── application/
│   │   │   ├── domain/
│   │   │   ├── infrastructure/
│   │   │   ├── llm/
│   │   │   └── agents/
│   │   ├── migrations/
│   │   └── tests/
│   └── web/
├── data/
│   └── uploads/
├── infra/
├── docs/
├── compose.yaml
└── .env.example
```

边界要求：

- `domain` 不依赖 FastAPI、LangChain、数据库客户端或模型 SDK。
- `application` 负责用例和事务，不包含 HTTP 细节。
- `llm` 封装模型、Prompt、Retriever 和结构化输出。
- `agents` 只通过声明过的工具调用 application service。
- `infrastructure` 实现数据库、向量、模型和文件存储适配器。
- API 层只做输入校验、鉴权（未来）和响应映射。

## 7. 页面最小集合

MVP 只实现五个一级页面：

1. 首页：今日待复习、最近学习、整体掌握度。
2. 知识库：创建知识库、上传资料、查看处理状态。
3. 题库：按知识点筛选、预览、编辑、启用和停用题目。
4. 学习工作台：诊断、练习、复习、模拟考试和讲解。
5. 学习进度：知识点掌握度、答题历史和复习计划。

不做独立“设置中心”。模型和存储配置先由 `.env` 完成。

## 8. 最小 API 边界

下列接口只定义资源和职责，详细请求响应在实现时写入 `docs/接口文档`。

### 知识库与资料

```text
POST   /api/knowledge-bases
GET    /api/knowledge-bases
GET    /api/knowledge-bases/{id}
PATCH  /api/knowledge-bases/{id}

POST   /api/knowledge-bases/{id}/materials
GET    /api/knowledge-bases/{id}/materials
GET    /api/materials/{id}
DELETE /api/materials/{id}
GET    /api/ingestion-jobs/{id}
```

### 知识点与题库

```text
GET    /api/knowledge-bases/{id}/knowledge-points
PATCH  /api/knowledge-points/{id}

POST   /api/materials/{id}/question-generation-jobs
GET    /api/questions
GET    /api/questions/{id}
PATCH  /api/questions/{id}
POST   /api/questions/{id}/activate
POST   /api/questions/{id}/disable
```

### 学习与复习

```text
POST   /api/study/sessions
GET    /api/study/sessions/{id}
GET    /api/study/sessions/{id}/events       # SSE
POST   /api/study/sessions/{id}/answers
POST   /api/study/sessions/{id}/finish

GET    /api/mastery
GET    /api/reviews/due
GET    /api/study/history
```

约束：

- 创建答案请求必须携带客户端生成的 `submission_id`，用于幂等。
- 后台任务接口立即返回 `job_id`，不能让上传请求等待解析和题库生成完成。
- SSE 只传输学习事件和增量文本，最终事实仍以普通查询接口和数据库为准。
- MVP 不提供 `/users`、`/roles`、`/permissions`、`/tenants` 等兼容接口。

## 9. 迁移方式

### 9.1 禁止整仓复制

不得把 `eap` 或 `eap-chat` 整体复制到 StudyAgent 后再删除。这样会把旧 Git 历史、企业字段、密钥、部署文件、重复依赖和大文件一起带入新项目。

### 9.2 白名单迁移流程

每次迁移一个能力：

1. 写出该能力的新接口和新数据模型。
2. 在旧项目定位最小实现文件。
3. 复制算法或纯工具函数，不复制服务入口和企业 SQL。
4. 改写为新项目的领域模型和 Repository 接口。
5. 清除固定地址、密钥、企业名称和旧表名。
6. 为正常、失败和边界场景补测试。
7. 通过测试后才允许进入主链路。

建议首批迁移顺序：

1. 文本切块和页码/标题元数据提取。
2. 文件上传与解析任务。
3. LLM/Embedding 调用适配器。
4. 题目结构化生成和去重。
5. SSE 输出工具。
6. Markdown 与引用展示组件。

## 10. 实施阶段与完成条件

### P0：迁移闸门

- 确认企业代码与前端代码的个人使用、修改和公开权限。
- 轮换旧仓库出现过的云密钥、模型 Key、第三方 Secret 和数据库密码。
- 新建干净仓库，不携带旧 `.git`。
- 建立 secret scan 和基础 CI。

完成条件：可以明确说明每一类被迁移代码的来源和授权，仓库扫描无明文 Secret。

### P1：资料到题库

- 建立 FastAPI、Vue、PostgreSQL、Milvus、Redis 和 MinIO。
- 创建知识库并上传资料。
- 后台完成解析、切块、知识点抽取和题目生成。
- 页面可查看生成题目及其原文引用。

完成条件：给定一份 PDF，能稳定生成一组结构合法且可溯源的题目。

### P2：学习闭环

- 实现诊断、练习、复习和模拟考试。
- 实现判题、错因解释、掌握度更新和 SM-2。
- 生成本次总结和下一次复习任务。

完成条件：同一知识点多次答题后，掌握度和复习日期按确定性规则变化。

### P3：质量与展示

- 建立固定评测集。
- 评估知识点覆盖、题目可溯源率、重复率、判题一致率和引用准确率。
- 完善错误处理、日志和 Agent Trace。
- 编写接口和 Docker Compose 部署文档。

完成条件：新环境按部署文档可以一键启动，评测结果可复现。

## 11. MVP 验收标准

- 一条命令启动 API、Worker、Web、PostgreSQL、Milvus、Redis 和 MinIO。
- 上传资料后可以看到明确的处理中、成功或失败状态。
- 每道启用题目至少关联一个原始片段。
- 判题结果满足结构化 Schema，分数始终处于合法范围。
- 学习 Agent 不直接执行 SQL，不允许模型决定是否写库成功。
- 题目选择能说明“为什么现在出这道题”。
- 掌握度和复习时间由可测试算法更新，不由 LLM 自由生成。
- 核心领域逻辑单元测试覆盖率目标不低于 80%。
- 项目中不存在企业名称、企业地址、旧公网 IP、旧镜像地址和明文密钥。

## 12. 暂缓决策

以下问题等 MVP 主链路完成后再决定：

- 是否增加账号与云端多用户。
- 是否在低配置部署中提供 pgvector 作为 Milvus 的替代实现。
- 是否将 MinIO 切换为兼容 S3 的云对象存储。
- 是否支持视频、语音和完整多语言。
- 是否增加知识图谱、BKT、IRT 或 Elo。
- 是否拆分为多个独立服务。

这些能力都不能成为第一版的前置条件。
