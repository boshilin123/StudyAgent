## 1. 学习环境统一

默认解释器为 `apps/api/.venv/Scripts/python.exe`，Python 3.12。已按开发锁安装依赖，并以 `--no-deps -e apps/api` 安装项目。


## 2. 命名和职责

- **Model / 模型**：`get_chat_model` 按用途创建出题、答后讲解和辅导模型。
- **Chain / 固定链**：`create_knowledge_point_chain`、`create_question_generation_chain` 创建 LCEL 链；`build_generation_context` 构建文本，区别于 Runtime Context。
- **Agent / 智能体**：`create_tutor_agent` 构建会调用工具的单辅导 Agent；开发 subagent 不属于产品架构。
- **Context / 运行上下文**：`TutorContext` 固定访问范围和轮次锚点。
- **State / 图状态**：`TutorState` 保存消息和证据，通过 reducer / Command 更新。
- **Snapshot / 业务快照**：`LearningSessionSnapshotStore`、`RedisLearningSessionSnapshotStore` 缓存可从 PostgreSQL 重建的学习会话。
- **Checkpointer / 检查点**：`AsyncPostgresSaver` 保存图执行状态；业务接受指针限定已提交历史。
- **Workflow / 执行轨迹**：`WorkflowRunModel`、`WorkflowStepModel` 记录运行，兼容历史物理表 `agent_runs`、`agent_steps`。
- **Index / 索引**：资料与题目双索引服务于不同对象，区别于 Dense/BM25 双路召回。

教学采用当前名称，旧名称保留兼容 alias。历史设计文档已标注状态；README 和源码导读已纠正出题检索、Token 分块和 LangGraph 状态混淆。无需因教学命名迁移数据库。

## 3. 实现与教学示例对齐

资料处理入口：`ingestion/parsers.py`、`chunking.py::build_chunks`、`embeddings.py`、`vector_index.py::MilvusDocumentIndex`。

辅导 RAG：`application/retrieval.py::LearningMaterialRetrieval.search/revalidate` 从向量索引取候选，再核对 PostgreSQL 资料归属、ready 状态、哈希与引文。学习记录走 `application/learning_queries.py`，不是向量检索。

受控出题：`question_generation/tasks.py`、`chains.py`、`schemas.py`、`quality.py::validate_question_drafts`。程序决定步骤，模型生成结构化数据；当前按顺序选取材料片段。

辅导 Agent：`agents/tutor/agent.py`、`tools.py`、`middleware.py`、`validation.py`，配合 `application/tutoring.py` 理解最终提交。工具只读业务事实，判分和复习由确定性逻辑处理。

检查点：`infrastructure/checkpointer.py` 显式初始化框架表，API 启动只探测。`TutorService` 从业务接受指针重建已提交历史，不盲目恢复最新检查点。

[三个可运行实验](../../examples/learning/README.md) 分别覆盖分块与上下文、真实 Agent 图的工具循环、手写 StateGraph 的分支和审核恢复。手写图使用固定资料与内存检查点，人工审核属于教学实验。

## 4. 本次验收与边界

默认 v1 环境运行全部非 integration 测试：149 项通过，41 项 integration 未在这一步执行。Ruff 通过。

真实 PostgreSQL 辅导验收：19 项通过，使用 `study_agent_test_upgrade` 隔离库。覆盖跨库/错误候选过滤、材料失效、幂等、锁、恢复、失败草稿隔离和业务只读保护；仍使用脚本化模型与显式向量候选。

三个实验已实际运行通过。长资料固定样本有 64 个片段，仅第 1～37 页进入输入，说明覆盖限制；通过测试不代表材料完整覆盖。正常、空资料、审核批准/拒绝和缺资料路径都有实际输出。

真实供应商和浏览器结果及小样本逐条审阅见 JSON 与文末补充。真实供应商输入限定为用户授权的 TCP 短文、两个问题及隔离库模拟记录。小样本审阅不能作为 40 条独立人工标注或通用质量指标。

### 4.1 最终复验与样本审阅

逐条审阅首次真实输出后发现，占位题干“测试题0”不能支持具体错因诊断。已将该真实验收 fixture 改为“TCP 通过三次握手建立连接。”，并增加生产提示约束：结合题干、作答和解析；题干无信息时不得仅凭来源推断考点；小样本不能泛化。Prompt 版本为 `tutor-v1.1`，图结构版本保持 `tutor-v1`，trace 改为引用统一版本常量。

修改后，57 项相关离线回归通过；19 项 PostgreSQL 和 1 项真实供应商测试再次通过。供应商测试包含两个实际问题：资料问答与近期错题分析。

- 资料回答正确说明 SYN、SYN+ACK、ACK 顺序和握手作用，返回第 2 页当前资料引用；模型耗时约 3.77 秒，仅此本机小样本。
- 错题回答读取进度、近期错题和已作答上下文，正确报告 1 次作答、0 次正确、掌握度 0.24；引用来自当前资料，复习建议标为未写入计划。模型耗时约 6.88 秒。
- 错因只凭判断题和一次作答不能确定。回答已说明推断限制，但仍出现“尚未掌握”的偏强措辞；PDF 应将其讲解为单次错答与算法估计，不能视为确定诊断。提示词是约束措施，不能保证所有模型回答语义正确。

前端类型检查通过；38 项真实 Chrome＋HTTP fixture 测试通过，原跳过的后端链路测试已另行启用并通过。该额外案例验证真实 Vue→HTTP API→create_agent→PostgreSQL/Milvus→刷新与归档，模型为脚本化 fixture；39 个不同浏览器案例已完成，不将它称为真实模型浏览器端到端测试。隔离服务使用替代的测试启动生命周期，因此其普通 health/ready 503 不用于生产就绪结论。

Mypy 检查 78 个源文件通过，生产代码与新增 Python 实验 Ruff 通过，准备脚本通过 Windows PowerShell 5.1 语法检查。测试实体和本次临时浏览器服务在验收结束后清理。

## 5. 正式 PDF 目录

命名采用两位编号：`第01章_项目全貌与学习闭环.pdf` 至 `第08章_自适应学习与评估复盘.pdf`。每章对应真实源码、实验输入、输出和练习。

1. **第01章：项目全貌与学习闭环**。区分资料处理、出题、作答和辅导；阅读 README、路由和领域模型。练习：画出问答与作答的调用路径。
2. **第02章：资料解析、字符分块与元数据**。阅读 parser、`build_chunks`；解释页码、标题、稳定 ID 和重叠。实验：`rag_context.py` 的分块部分。
3. **第03章：Embedding、Milvus 与 RAG 检索**。阅读 Embedding、索引、metadata 过滤和 `LearningMaterialRetrieval`。练习：跟踪跨库与失效资料测试。
4. **第04章：LCEL 出题、结构化输出与质量门禁**。阅读两个链工厂、Schema、质量门禁和 Celery；解释长材料限制。练习：制造虚假引文并观察拒绝。
5. **第05章：辅导 Agent、工具与 Middleware**。阅读 ToolRuntime、必需取证、预算和最终校验。实验：`agent_tool_loop.py` 的正常与空资料案例。
6. **第06章：LangGraph 节点、条件边与中断恢复**。运行 `langgraph_review.py`，再映射生产 State、reducer、Command。练习：批准、拒绝及不同 thread_id 恢复。
7. **第07章：业务状态、检查点与幂等恢复**。阅读 TutorService、repository、checkpointer 和 Redis snapshot。练习：失败草稿隔离、重复请求不重复运行。
8. **第08章：自适应学习与评估复盘**。阅读 `adaptive_selection.py`、`study.py`、判分、掌握度、复习与 evaluation。练习：解释选题理由和评测范围。
