# P10 可靠性加固与回归验证

验证日期：2026-09-30。范围为单用户 StudyAgent 的可靠性问题、干净环境复现和学习闭环回归；不将自动化通过等同于人工题目质量审核或公网安全认证。

## 1. 已修复问题

### 判分与学习状态

- 填空答案保留负号、小数点、斜杠、加号和内部空格；不再将 `-1` 判为 `1`、`1.5` 判为 `15`、`TCP/IP` 判为 `TCPIP`。Unicode 宽度、大小写、外围空白和有限句末标点仍可归一化；同义答案使用显式别名。
- 提交 ID 使用 PostgreSQL 事务级 advisory lock，随后锁定会话；同 ID 的并发请求只产生一次事实写入，相同载荷返回重放结果，不同载荷返回冲突。
- 题目和知识点统计更新协调加锁，避免不同会话丢失掌握度与复习累计。题目启用、来源删除与作答也使用一致的题目锁。
- 讲解失败不撤销已经提交的判分、掌握度和复习事实；Redis 缓存丢失或 JSON 损坏时可从数据库恢复。
- 当前题目已停用或失去全部来源时不继续提供该题；提交返回明确冲突，用户可以结束会话。
- 自适应选题不再只扫描前 500 道题；诊断模式优先覆盖尚未充分出现的知识点。

### 任务、来源与向量

- 排队中的初次上传也阻止删除和重处理；同资料的解析与生成互斥。
- 派发异常会将已创建任务记录补偿为失败，使用 `TASK_QUEUE_UNAVAILABLE`，而不是永久卡在等待状态；随后允许重试。
- Celery 正在等待重试时任务保持运行，避免放行竞争任务。重试关闭之前中断的 Agent Trace；完成任务的重复投递不再调用模型。
- 重新切块先移除失效来源与旧数据库片段，再写入新片段，避免片段序号唯一约束冲突；每次索引重试都清理过期向量。
- 删除资料或失效片段后，失去全部来源的题目停用并清理题目向量；还有其他有效来源的题目保留。历史答题记录不删除。
- 检索结果用数据库中的就绪资料与现存片段再次过滤，避免暴露失败重建或遗留向量。
- 修复真实数据库中题目向量更新后读取服务器端 `updated_at` 触发 `MissingGreenlet` 的问题。

### 前端、部署与复现

- 前端持久化未确认的作答载荷；超时、重试和刷新使用同一个 `submission_id`。明确的 400/404/409/422 拒绝会清除该载荷，允许修改后重新提交；网络和服务端暂时失败继续保留。
- 就绪检查实际探测 PostgreSQL、Redis、Broker、Milvus 与存储，带超时且隐藏异常细节；Worker 使用 Celery 自身 ping 检查。
- Python 运行与开发依赖使用精确版本锁；Docker 按锁安装后以 `--no-deps` 安装应用。Python 基础镜像与 RustFS 镜像固定 digest。
- 干净环境脚本同时复制前后端源文件，使用全新的 npm 目录和 Python venv，逐条检查命令退出码。测试数据库未配置时会明确报告集成测试跳过，不伪装为完整验收。
- 开发编排的宿主机映射仅绑定 `127.0.0.1`。生产环境必须设置至少 32 位 URL-safe 的共享 Bearer 令牌；前端可以录入。该门禁不是多用户权限系统。
- CI 增加 PostgreSQL 迁移与事务回归、浏览器测试、实际 Compose 启动与就绪检查；后端覆盖率门槛提高到 80%。

## 3. 复现方法

### Windows 隔离验证

准备 Python 3.12、Node.js 22、可用 Chromium/Chrome 和 Docker。开发服务按 `.env` 配置启动。先创建专用测试数据库并提供异步 PostgreSQL 连接串，不要使用 `study_agent` 业务数据库：

```powershell
# 连接信息由本机配置或 Secret 提供，以下为占位值，不可直接运行。
$env:TEST_DATABASE_URL = 'postgresql+asyncpg://<user>:<password>@127.0.0.1:55432/study_agent_test_p10'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\验证干净环境.ps1
```

脚本执行锁定安装、迁移、前后端测试和静态检查。它不会创建数据库；数据库须事先存在。没有 `TEST_DATABASE_URL` 时只跑非数据库测试并报告跳过；`-SkipBackendInstall` 只验证前端。每次创建独立 `tmp/clean-environment-*` 目录并保留，方便排查失败。

### 后端独立验证

在 `apps/api` 下执行，连接串从测试专用环境变量提供：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.lock
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
.\.venv\Scripts\python.exe -m pip check
$env:DATABASE_URL = $env:TEST_DATABASE_URL
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m pytest --cov=study_agent --cov-fail-under=80
.\.venv\Scripts\python.exe -m ruff check --no-cache .
.\.venv\Scripts\python.exe -m mypy --no-incremental study_agent
```

迁移前必须确认目标是专用测试库。生产锁为 `requirements.lock`，开发及测试锁为 `requirements-dev.lock`；新增依赖时需重新编译并验证两个锁，不直接手改其中的解析版本。

## 4. 保留边界

- 任务派发补偿验证了显式异常，不提供数据库与 Broker 的跨系统原子提交；进程在提交和派发之间崩溃仍需进一步采用 durable outbox。
- PostgreSQL、对象存储与向量库没有分布式事务。清理操作可重试且查询会过滤失效项，但外部服务部分成功后进程崩溃仍需要运维对账或后台修复机制。
- 扩大候选扫描消除了前 500 题偏差，但并非大规模题库的分页评分或性能优化；未执行固定硬件负载测试。
- 59 道历史题目的人工审核仍为 pending；自动来源关联与结构校验不能给出人工正确率。既有 30 条 TCP 小范围检索基线不能外推为跨主题能力。
- 共享令牌不提供账号、所有权隔离、细粒度权限、限流或病毒扫描；公网发布仍需 HTTPS 和这些安全能力。
- 当前修改与验证证据在工作区，未在本轮自动提交或推送。
