# StudyAgent 数据库设计

状态：初稿  
关系数据库：PostgreSQL 16  
向量数据库：Milvus  
范围：单用户 MVP

## 1. 设计原则

- 不迁移旧企业表，不保留 `sp_` 前缀。
- 不建立用户、租户、公司、部门、岗位、角色和权限表。
- 知识库是资料、知识点、题目和学习目标的顶层边界。
- 原始资料、切块、知识点和题目分别建模，禁止只把题目塞入向量库。
- PostgreSQL 保存业务事实和 Milvus 主键；Milvus 保存向量及检索过滤所需的最小 metadata。
- 答题记录是不可变事件；掌握度和复习任务是可更新状态。
- Agent 的决定和工具调用可追踪，但不把大段 Prompt 全部塞入业务表。
- 所有时间使用带时区的 `timestamptz`，统一存 UTC。
- 主键使用 UUID；展示序号另设字段，不依赖自增 ID。

## 2. 核心关系

```text
knowledge_bases
  ├── materials
  │     └── document_chunks
  ├── knowledge_points
  │     ├── questions
  │     │     └── question_sources ── document_chunks
  │     ├── mastery_records
  │     └── review_tasks
  ├── learning_goals
  └── study_sessions
        └── answer_records ── questions

ingestion_jobs 关联 material
agent_runs / agent_steps 记录 Agent Trace
```

## 3. 表定义

下面是逻辑字段，不代表最终迁移脚本的完整 SQL。实现时补充外键名称、约束和更新时间触发方式。

### 3.1 `knowledge_bases`

表示一个学习主题，例如“计算机网络”“软考系统架构师”。

字段：

- `id uuid primary key`
- `name varchar(200) not null`
- `description text null`
- `language varchar(20) not null default 'zh-CN'`
- `status varchar(20) not null default 'active'`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`

约束：`status in ('active', 'archived')`。

### 3.2 `materials`

表示用户上传的一份原始资料。

字段：

- `id uuid primary key`
- `knowledge_base_id uuid not null references knowledge_bases(id)`
- `title varchar(300) not null`
- `original_filename varchar(500) not null`
- `media_type varchar(100) not null`
- `storage_uri text not null`
- `sha256 char(64) not null`
- `size_bytes bigint not null`
- `language varchar(20) not null`
- `parse_status varchar(20) not null default 'pending'`
- `parser_version varchar(50) null`
- `error_message text null`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`

约束：同一知识库中 `(knowledge_base_id, sha256)` 唯一，避免重复上传。

### 3.3 `document_chunks`

原始资料的可检索文本单元。

字段：

- `id uuid primary key`
- `material_id uuid not null references materials(id)`
- `chunk_index integer not null`
- `content text not null`
- `token_count integer not null`
- `page_start integer null`
- `page_end integer null`
- `heading_path text[] not null default '{}'`
- `parent_chunk_id uuid null references document_chunks(id)`
- `content_hash char(64) not null`
- `vector_id varchar(100) null`
- `embedding_model varchar(100) null`
- `created_at timestamptz not null`

约束：`(material_id, chunk_index)` 唯一。

索引：

- `material_id`
- `content_hash`
- `vector_id`，用于定位或清理 Milvus 中的对应向量

### 3.4 `knowledge_points`

知识库中的学习单元。

字段：

- `id uuid primary key`
- `knowledge_base_id uuid not null references knowledge_bases(id)`
- `name varchar(300) not null`
- `description text null`
- `canonical_key varchar(300) not null`
- `importance numeric(4,3) not null default 0.5`
- `difficulty integer not null default 1`
- `source varchar(20) not null default 'agent'`
- `status varchar(20) not null default 'active'`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`

约束：

- `(knowledge_base_id, canonical_key)` 唯一。
- `importance between 0 and 1`。
- `difficulty between 1 and 5`。

MVP 不建立知识图谱关系表。需要先修知识点时，可后续增加 `knowledge_point_relations`，不能阻塞首版。

### 3.5 `knowledge_point_sources`

记录知识点来源，避免知识点成为无法追溯的模型结论。

字段：

- `knowledge_point_id uuid references knowledge_points(id)`
- `chunk_id uuid references document_chunks(id)`
- `relevance numeric(4,3) not null default 1`
- `primary key (knowledge_point_id, chunk_id)`

### 3.6 `questions`

字段：

- `id uuid primary key`
- `knowledge_base_id uuid not null references knowledge_bases(id)`
- `knowledge_point_id uuid not null references knowledge_points(id)`
- `question_type varchar(30) not null`
- `stem text not null`
- `options jsonb null`
- `correct_answer jsonb not null`
- `scoring_points jsonb not null default '[]'`
- `explanation text not null`
- `difficulty integer not null`
- `max_score numeric(6,2) not null default 10`
- `status varchar(20) not null default 'draft'`
- `generation_run_id uuid null references agent_runs(id)`
- `content_hash char(64) not null`
- `vector_id varchar(100) null`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`

约束：

- 当前生成类型为 `single_choice`、`fill_blank`、`true_false`；数据库兼容后续加入 `short_answer`。
- `difficulty between 1 and 5`。
- `max_score > 0`。
- `status in ('draft', 'active', 'disabled', 'rejected')`。
- 同一知识库中 `(knowledge_base_id, content_hash)` 唯一。

`correct_answer` 使用 JSON，是为了同时表达单值、多接受答案和单选项 key。进入领域层后必须解析为具体题型模型，不能在业务代码里到处操作任意 JSON。

### 3.7 `question_sources`

字段：

- `question_id uuid references questions(id)`
- `chunk_id uuid references document_chunks(id)`
- `quote text not null`
- `rank integer not null default 1`
- `primary key (question_id, chunk_id)`

每道 `active` 题目必须至少有一条来源。该规则由 application service 和数据库延迟校验共同保证。

### 3.8 `learning_goals`

字段：

- `id uuid primary key`
- `knowledge_base_id uuid not null references knowledge_bases(id)`
- `title varchar(300) not null`
- `target_date date null`
- `target_mastery numeric(4,3) not null default 0.8`
- `daily_minutes integer not null default 30`
- `status varchar(20) not null default 'active'`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`

目标与知识点权重若 MVP 确有需要，再增加 `learning_goal_knowledge_points`。第一版可以直接覆盖整个知识库。

### 3.9 `study_sessions`

字段：

- `id uuid primary key`
- `knowledge_base_id uuid not null references knowledge_bases(id)`
- `mode varchar(20) not null`
- `status varchar(20) not null default 'active'`
- `planned_question_count integer not null`
- `answered_question_count integer not null default 0`
- `correct_count integer not null default 0`
- `incorrect_count integer not null default 0`
- `total_score numeric(8,2) not null default 0`
- `max_total_score numeric(8,2) not null default 0`
- `question_types jsonb not null`
- `difficulty_min integer not null`
- `difficulty_max integer not null`
- `started_at timestamptz not null`
- `finished_at timestamptz null`

约束：

- `mode in ('diagnostic', 'practice', 'review', 'mock_exam')`。
- `status in ('active', 'completed', 'abandoned')`。

`mock_exam` 在开始时写入全部题目；其他模式每次确定下一题时追加一条，以便恢复和审计。

### 3.10 `session_questions`

字段：

- `session_id uuid references study_sessions(id)`
- `question_id uuid references questions(id)`
- `sequence integer not null`
- `selection_reason jsonb not null`：选择原因代码、说明、目标难度和评分因子。
- `priority_score numeric(7,6) not null`：当次确定性选题综合分。
- `primary key (session_id, sequence)`
- `unique (session_id, question_id)`

普通自适应会话也可记录已选择题目，便于恢复和审计。

### 3.11 `answer_records`

每次提交一条不可变记录。重复 HTTP 请求通过 `submission_id` 幂等。

字段：

- `id uuid primary key`
- `submission_id uuid not null unique`
- `session_id uuid not null references study_sessions(id)`
- `question_id uuid not null references questions(id)`
- `knowledge_point_id uuid not null references knowledge_points(id)`
- `answer jsonb not null`
- `score numeric(6,2) not null`
- `max_score numeric(6,2) not null`
- `verdict varchar(20) not null`
- `feedback text not null`
- `elapsed_seconds integer not null`
- `explanation_data jsonb null`：答后讲解、生成状态及程序绑定的真实引用。
- `answered_at timestamptz not null`

约束：

- `(session_id, question_id)` 唯一，防止同一会话重复推进同一道题。
- `verdict in ('correct', 'incorrect')`。

P4 只处理确定性客观题，不存在 LLM 判题失败状态；主观题启用时再扩展判题字段。

答题事实先在主事务中提交；LangChain 讲解在事务外生成，再单独写入 `explanation_data`，避免外部模型调用期间持有会话行锁。

### 3.12 `mastery_records`

每个知识点仅一条当前状态。

字段：

- `knowledge_point_id uuid primary key references knowledge_points(id)`
- `knowledge_base_id uuid not null references knowledge_bases(id)`
- `mastery_score numeric(4,3) not null default 0.3`
- `answered_count integer not null default 0`
- `correct_count integer not null default 0`
- `recent_accuracy numeric(4,3) not null default 0`
- `confidence numeric(4,3) not null default 0`
- `updated_at timestamptz not null`

约束：所有分数和置信度在 `[0, 1]`。

为了可审计，掌握度变化历史从 `answer_records` 重放；MVP 不额外建立事件表。若算法频繁升级，再增加 `mastery_events`。

### 3.13 `review_tasks`

字段：

- `id uuid primary key`
- `knowledge_point_id uuid not null unique references knowledge_points(id)`
- `knowledge_base_id uuid not null references knowledge_bases(id)`
- `due_at timestamptz not null`
- `interval_days integer not null default 1`
- `repetitions integer not null default 0`
- `ease_factor numeric(4,2) not null default 2.5`
- `last_quality integer not null`
- `status varchar(20) not null default 'pending'`
- `updated_at timestamptz not null`

约束：

- `ease_factor >= 1.3`。
- `status in ('pending', 'completed')`。

同一知识点只保留当前复习状态，历史通过答题记录回放。

### 3.14 `ingestion_jobs`

字段：

- `id uuid primary key`
- `material_id uuid not null references materials(id)`
- `status varchar(20) not null`
- `stage varchar(30) not null`
- `progress integer not null default 0`
- `generation_config jsonb not null default '{}'`
- `error_code varchar(100) null`
- `error_message text null`
- `started_at timestamptz null`
- `finished_at timestamptz null`
- `created_at timestamptz not null`

约束：`progress between 0 and 100`。

阶段建议：`uploaded`、`parsing`、`chunking`、`embedding`、`extracting_points`、`generating_questions`、`validating`、`completed`。

### 3.15 `agent_runs`

字段：

- `id uuid primary key`
- `agent_type varchar(30) not null`
- `subject_type varchar(30) not null`
- `subject_id uuid not null`
- `status varchar(20) not null`
- `model varchar(100) null`
- `prompt_version varchar(50) null`
- `input_summary jsonb not null default '{}'`
- `output_summary jsonb not null default '{}'`
- `prompt_tokens integer not null default 0`
- `completion_tokens integer not null default 0`
- `error_message text null`
- `started_at timestamptz not null`
- `finished_at timestamptz null`

`subject_id` 是逻辑关联，不设多态外键。application service 必须校验目标存在。

### 3.16 `agent_steps`

字段：

- `id uuid primary key`
- `run_id uuid not null references agent_runs(id)`
- `sequence integer not null`
- `node_name varchar(100) not null`
- `tool_name varchar(100) null`
- `input_summary jsonb not null default '{}'`
- `output_summary jsonb not null default '{}'`
- `status varchar(20) not null`
- `duration_ms integer null`
- `error_message text null`
- `created_at timestamptz not null`

约束：`(run_id, sequence)` 唯一。

Trace 中只存摘要和 ID，不存完整资料正文、密钥或超长模型上下文。

## 4. 删除策略

- 知识库默认归档，不立即物理删除。
- 删除资料时，必须处理其 chunks、知识点来源和题目来源；若题目失去全部来源，自动禁用。
- 答题记录不做级联物理删除，除非用户明确执行“清空全部数据”。
- MVP 可提供重置学习进度：删除 answer_records、mastery_records、review_tasks 和 study_sessions，但保留资料与题库。

## 5. 事务边界

必须在单一事务中完成：

### 保存生成题目

1. 校验知识点和来源 chunk。
2. 写入 question。
3. 写入 question_sources。
4. 写入 Agent step 结果。

### 提交答案

1. 使用 `submission_id` 检查幂等。
2. 写入 answer_record。
3. 更新 mastery_record。
4. 更新 review_task。
5. 更新 study_session 统计。

任何一步失败都回滚，Agent 不负责补偿数据库的部分写入。

## 6. 初始索引建议

- `materials(knowledge_base_id, created_at desc)`
- `document_chunks(material_id, chunk_index)`
- `knowledge_points(knowledge_base_id, status)`
- `questions(knowledge_base_id, knowledge_point_id, status, difficulty)`
- `study_sessions(knowledge_base_id, started_at desc)`
- `answer_records(session_id, answered_at)`
- `answer_records(knowledge_point_id, answered_at desc)`
- `review_tasks(status, due_at)`
- `ingestion_jobs(material_id, created_at desc)`
- `agent_steps(run_id, sequence)`

Milvus 索引参数应在真实数据量和召回评测集明确后配置，不在空库阶段盲目调参。PostgreSQL 中的 `vector_id` 用于数据一致性检查和删除补偿，不承担相似度检索。

## 7. 不进入 MVP 的表

- users、roles、permissions、tenants。
- companies、departments、positions。
- announcements、leaderboards、licenses。
- courses、videos、video_progress。
- chat_messages 独立大表；学习交互先由 session + answer_records 表达。
- knowledge_point_relations；等确实需要先修关系再增加。
- model_configs；第一版使用环境变量。

这些表后续只能由明确的产品需求引入，不能为了兼容旧库提前建立。
